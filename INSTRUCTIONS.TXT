By default you write programs in java 21.

If your task is to refactor, then observe the following rules. If you are asked to add functionality you do not have to refactor.

NOTE: ALL of the rules below are MANDATORY. Some of the rules are different from usual practice (e.g. we do not allow constructors, hence no constructor parameter injection),
these rules overwrite those.

All program logic is implemented in Service units. Service units should be testable, so everything which
makes testing hard (e.g. IO) are moved to Components.
Components hold external stuff which should be mocked out in tests.
Simple utility functions can go to Util units.
To minimize redundancy, constants are moved to Constant units.
Data structures are in Data units. If you want to store or modify data, use Repositories.
Sometimes the program needs to provide an object-oriented API. Delegate units are to combine Data and Services into an OOP unit.
Sometimes the framework requires the existence of some special classes. They are the Glue.

Testing is even more important than production code. Tests are in Test units. They correspond to Services. Test data is extracted to TestData units. To make testing easier, everything is stubbed out. The stubs (normally of Service and Component unit) are in Stub units.

remember: ALL rules are MANDATORY
The rules regarding the different types of units.

Service
- class name ends with Service
- have a spring @Service annotation
- have one public method called apply. No other public methods.
- all constants are extracted to a Constants unit
- dependencies are in @Autowired fields. the field name is the same as the service name lowercased, without 'Service' at the end.
- no other fields
- a service is maximum 25 LoC long, anything longer is refactored to another Service or Util unit.
- everything which would make unit testing cumbersome (using network, filesystem, console, (basically any OS service) even indirectly
  should be dependency (at the end, a Component, possibly through a Service if there 

Constant
- an interface with name ending in Constants
- contains only constants

Util
- a class with name ending in Util
- only public static methods

Data
- a record with name ending in Data
- only field declarations

Repository
- an interface with name ending with repository
- with @Repository spring annotation
- extends CrudRepository, with String ID

Delegate
- a class with io.github.magwas.konveyor.annotations.Delegate annotation
- contains one 'self' field referencing a Data unit
- dependencies are fields in the same way as for a Service
- have exactly one method for each field which calls the service with self as the first argument
- this emulates the classical class which have both data encapsulated and logic.

Component
- a class with @Component annotation
- contains methods returning objects of external dependencies. Method names starts with get, and does not have parameters unless absolutely necessary.
- no fields, no constructor

Glue
- annotated with io.github.magwas.konveyor.annotations.Glue
- contains the necessary things required by frameworks and dependencies
- for code which does not fit other categories
- Glue should not contain business logic. never touch a glue unless specifically instructed.

The following are test code. they reside in packages corresponding to the code they test, with '.test' appended to the package name

TestData
- an interface with name ending with TestData
- contains only constants

Stub
- a class stubbing a service or component. Its name starts with the service/component name and ends with Stub
- its package is the package of the service with '.tests' appended. E.g. stubs for classes in io.github.magwas.coder should eb in io.github.magwas.coder.tests
- it either have a io.github.magwas.konveyor.testing.IndirectlyTested annotation and empty body, or
- have a public static <servicename> stub() method returning a Mockito mock.
- all constants are from implemented TestData units
- if the stub needs to return different values based on the same input based on the state of the environment,
  it should use TestBase.environmentState to figure out the correct answer.

Test
- a class with the same name as the service, with 'Test' added
- The tested service is in a field with @InjectMocks annotation
- extends io.github.magwas.konveyor.testing.TestBase
   that class already handles injecting the stubs into the tested class
   also contains public static String environmentState, which is initialized to null before each tests
   there is a void given(String newState) which sets environmentState to newState.
- all constants are from implemented TestData units
- all tests use @DisplayName to document what is tested
- tests should not execute dependencies, network, or filesystem. These should all be stubbed out.
- a Test unit can only contain @njectMocks field, tests, @BeforeEach and @AfterEach methods
  - stubbing and mocking go to Stub units
  - test data go to TestData units
  - helper functions, new assertion methods go to TestUtil units

TestUtil
- a class with a name ending to 'TestUtil'
Miscellanous rules:
- Only Glue and Delegate components can have constructors. No other constructor is allowed.
- Autowire only fields. do not autowire constructor, as constructors are not allowed.
- No comment in the code. If a comment is needed, probably something should be refactored to a well-named method.
- only emit new or changed files in response
- all units are in their own files
- no file contains more than one of any of class, interface, record
- never create spring configuration classes or spring beans unless specifically instructed

Always double check that the code you created is adhering to ALL of the rules.
